# UA Env Switcher

A smart, lightweight Chrome extension (Manifest V3) for anyone who tests the
same app on several environments every day: **one click hops the current tab
between localhost / staging / production while keeping the exact route,
query, and hash** — plus quick actions to purge service-worker caches, swap
test accounts via storage profiles, and toggle feature flags.

No dependencies, no build step, ~30 KB of plain JS.

## Install (unpacked)

1. Open `chrome://extensions`
2. Enable **Developer mode** (top right)
3. Click **Load unpacked** and select this folder (`ua-env-switcher`)

## Use

- Toolbar popup → click an environment to switch (the current one shows as a chip)
- **Alt+Shift+E** anywhere → cycle to the next environment
- Right-click page → *Open this page in → …* or *Purge SW caches & hard reload*
- **Purge SW caches & hard reload** — unregisters every service worker, deletes every CacheStorage entry, then hard-reloads (the fix for stale PWA caches after a deploy)
- **Storage profiles** — snapshot the page's localStorage + sessionStorage under a name (per origin), apply another profile in one click, **Undo last apply** restores exactly what was there before
- **Feature flags** — every localStorage key matching your prefixes (default `flag_`, `feature_`, `ff_`) appears as a toggle (booleans) or an editable field (numbers/strings)
- **Manage environments…** (popup footer) → options page: add/edit/remove environments, edit flag prefixes, delete profiles, reset to defaults

## What makes it careful

| Signal | Behavior |
|---|---|
| origin matching | case-insensitive host, default ports stripped, ports distinguished (`:3000` ≠ `:5173`) |
| route preservation | path + query + hash are never touched — switching is a pure origin rewrite |
| validation | origins must be clean http(s) URLs; duplicates are rejected in the options page |
| flag typing | `'true'/'false'` toggle as booleans, numeric strings edit as numbers, everything else stays an opaque string |
| profiles | applied by clearing stale keys first, so removed keys disappear (not merged); one-step undo per origin |
| permission footprint | `activeTab` + `scripting` only — no host permissions, no install-time warning, nothing runs until you act |

## Structure

```
manifest.json          MV3 manifest (activeTab + scripting + storage + contextMenus)
background.js          service worker: switching, purge, profiles, flags, context menus
shared/envcore.js      pure env/URL/flag logic (no chrome.* or DOM — fully unit-tested)
shared/inject.js       content-bundle injection helper
content/env.js         page-side actions: purge, snapshot/apply, flag listing
popup/                 quick-switch UI
pages/options.html     environments / prefixes / profiles manager
icons/                 generated by tools/gen-icons.js
```

## Verify

```
node test/run-tests.js                       # unit tests (pure logic + fake Storage)
NODE_PATH=… node test/e2e.js                 # real-Chrome e2e (see header comment)
node tools/gen-icons.js                      # regenerate icons
NODE_PATH=… node tools/make-screenshot.js    # regenerate the store screenshot
```

The e2e suite serves `test/demo` on two local ports as two fake
environments and exercises the real content bundle against live
ServiceWorker / CacheStorage / localStorage APIs.

## Notes & limits

- Switching works on http(s) pages only (Chrome blocks `chrome.tabs.update` into privileged schemes from most pages anyway).
- Storage profiles cover localStorage + sessionStorage, not cookies — cookie-based sessions need the site's own login. (Keeps the permission list at zero host permissions.)
- Cache purge needs a secure context for `caches` (`https://` or `localhost`); on plain `http://` IPs the cache part is skipped.
- The Alt+Shift+E cycle follows the saved order in the options page; a page matching no environment jumps to the first one.
